# /save 작업 저장

클라우드 세션은 끝나면 컨테이너가 사라지고, 기기마다 파일도 따로다. **저장소(GitHub)에 push된 것만 남는다.** 그래서 저장 위치는 그 프로젝트의 **할 일 파일 하나**다. 새 파일을 늘리지 않는다.

할 일 파일 찾는 순서: 프로젝트 CLAUDE.md가 정한 파일, 다음으로 README가 가리키는 진행 파일(예: `05_운영/다음할일.md`, `05_진행상황.md`), 없으면 저장소 루트 `TASKS.md`.

## 순서
1. 끝난 일은 할 일 파일에서 지운다(취소선으로 남기지 않음). 결정이나 정정이 생겼고 프로젝트에 기록 파일이 있으면 거기에 1줄.
2. 할 일 파일 **맨 위**에 `## 이어서 할 곳`을 쓴다. 이전에 쓴 것은 덮어쓴다. **이 세션 일이 끝나서 다른 기기에서 이어서 할 게 없으면(커밋·배포만 남은 경우 포함) 쓰지 않는다.** 이 세션 몫으로 적힌 것은 지우고, 다른 세션 몫이 남아 있으면 그대로 둔다. 끝난 일을 이어서 할 곳에 남기지 않아야 `/go`가 다시 띄우지 않는다. 3번부터는 똑같이 한다.
   - 마지막으로 한 일 (한 줄)
   - 지금 작업 중인 곳: 파일 경로, 문서 링크나 ID, 브랜치, 돌고 있던 작업(워크플로 실행 번호 등)
   - 다음 한 걸음: 바로 시작할 수 있게 구체적으로
   - 내 결정이 필요한 것, 내가 눈으로 확인할 것
   - 이미 정한 규칙은 복사하지 말고 어느 파일 몇 절에 있는지만
3. **전체용 CLAUDE.md 맞추기**: `~/.claude/CLAUDE.md`와 저장소 사본 `.claude/global-CLAUDE.md`의 첫 줄 `갱신:` 시각을 비교해 더 새로운 쪽으로 다른 쪽을 덮어쓴다(이 기기에서 고쳤으면 사본에 반영). 파일을 하나 더 만들지 않는다. 저장소에 사본이 없으면 건너뛴다.
4. 커밋하고 push한다. 그 프로젝트의 브랜치 규칙을 따르고, 충돌하면 멈추고 알린다. push가 거절되면 fetch 후 merge해서 다시 올린다. 원격과 로컬이 같은지 확인한다. **push되지 않은 채로 끝내지 않는다.** 저장소가 없는 대화면 어디에 둘지 한 번만 묻는다.
5. 답은 "내 결정이 필요한 것 / 바꾼 것 / 알아낸 것"으로 쓰고, 마지막에 **다음 세션에서는 `/go`만 입력하면 된다**고 알린다(이어서 할 게 없으면 "이어서 할 일 없음, `/go` 필요 없음"으로 바꾼다). 새 세션에 따로 전할 결정이 있으면 그것만 한두 줄로 덧붙인다.
6. 답을 다 쓴 뒤 맨 마지막에 이 세션을 보관한다(`archive_session`, session_id `"self"`; 도구가 있을 때만, 앱이 허락을 물으면 따른다). 보관하면 대화가 끝나므로 이 호출은 답 끝에서 한 번만 한다. push가 끝나지 않았거나 내 결정을 기다리는 중이면 보관하지 않는다.

## 하지 않는 것
- 대화를 요약해 파일을 늘리기
- 정하지 않은 것을 확정해서 적기 (미정은 결정 대기에 둔다)
