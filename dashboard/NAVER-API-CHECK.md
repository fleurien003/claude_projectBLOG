# 네이버 API, 정말 연결돼 있나? — 확인 설계

> 결론부터: **지금 파이프라인 어디에서도 네이버 API를 호출하지 않습니다.**
> 전부 "브라우저로 사이트를 눈으로 보는" 방식이고, 그 브라우저는 은아님 컴퓨터에서 뜹니다.

## 확인해야 할 곳 6군데 (위에서부터 순서대로)

| # | 확인 지점 | 누가 | 결과 |
|---|---|---|---|
| 1 | 대시보드 페이지 소스 | Claude | ✅ 확인 완료 — API 호출 0건 |
| 2 | Routine에 저장된 커넥터 목록 | Claude | ✅ 확인 완료 — 네이버 없음 |
| 3 | Routine 프롬프트 본문 | Claude | ✅ 확인 완료 — 브라우저 방식 명시 |
| 4 | 노트북의 Claude 앱 커넥터/MCP 목록 | **은아님** | ⬜ 미확인 |
| 5 | 네이버 개발자센터 앱 등록 여부 | **은아님** | ⬜ 미확인 |
| 6 | 네이버 검색광고 API 라이선스 | **은아님** | ⬜ 미확인 |

---

## 1. 대시보드 페이지 소스 — API 호출 0건

페이지가 바깥과 통신하는 지점은 **딱 두 줄**입니다.

```
claude.use('sample')   // 글 쓰기
claude.use('db')       // 데이터 읽고 쓰기
```

`fetch`, `XMLHttpRequest`, `openapi.naver.com`, `client_id` — **하나도 없습니다.**
소스 주석에도 이렇게 적혀 있습니다.

> `// 페이지 안에서는 웹 조회·네이버 API를 쓸 수 없다.`

→ 대시보드는 애초에 API를 부를 수 없는 구조입니다. 이건 정상이고, 원래 설계가 그렇습니다.

## 2. Routine에 저장된 커넥터 — 네이버 없음

Routine은 실행될 때 **자기한테 저장된 커넥터만** 쓸 수 있습니다. 등록된 목록 전체입니다.

```
Google_Drive · Google_Calendar · Figma · Canva · Claude_Code_Remote · Notion
```

**네이버 관련 커넥터가 하나도 없습니다.** (`api_token_hint`도 비어 있음)

→ 설령 다른 데서 네이버 API를 연결해뒀더라도, **Routine이 돌 때는 그 도구를 못 씁니다.**

## 3. Routine 프롬프트 본문 — 브라우저 방식이라고 직접 써 있음

| Routine | 원문 |
|---|---|
| 체험단 선정 순찰 | "르나의 컴퓨터(Windows, Claude 데스크톱 앱)에 **연결되어 있어야** 브라우저 도구를 쓸 수 있다" |
| 블로그 글쓰기 | "**브라우저로** 해당 업체명의 네이버플레이스 정보를 확인해라" |
| 블로그 글쓰기 | "keywordsound.com은 자바스크립트 사이트라 **브라우저 자동화 도구로 직접 들어가야** 한다" |
| 홈피드 아침 | "WebSearch/WebFetch로 조사. **네이버 계열 도메인은 이 세션에서 차단**" |

→ 키워드 검색량조차 네이버 API가 아니라 **keywordsound.com이라는 제3자 사이트를 브라우저로 보는** 방식입니다.

## "내 노트북에서 명령했으면 API가 돌아가야 하는 거 아니야?"

여기가 핵심 오해 지점입니다.

```
은아님 노트북에서 Routine을 "만든다"
        ↓
Routine은 저장만 됨
        ↓
정해진 시간에 ☁️ 클라우드에서 실행된다   ← 노트북이 아님!
        ↓
클라우드가 쓸 수 있는 도구 = Routine에 저장된 커넥터 6개
        ↓
네이버 정보가 필요하면 → remote-devices로 은아님 컴퓨터를 원격 조종
        ↓
컴퓨터가 꺼져 있으면 → "오늘은 컴퓨터가 연결 안 돼서 못 했어요" 하고 종료
```

**즉 노트북에 네이버 API를 깔아뒀더라도 Routine은 그걸 못 씁니다.**
노트북에서 직접 Claude와 대화할 때만 쓸 수 있어요.

그리고 집 노트북이냐 회사 노트북이냐는 **Routine 입장에선 상관이 없습니다.**
대신 "그 시각에 켜져 있고 Claude 데스크톱 앱이 열려 있는 컴퓨터가 있느냐"가 전부입니다.

## 은아님이 확인해주실 것 (4~6번)

### 4. 노트북의 Claude 앱 커넥터 목록
Claude 데스크톱 앱 → 설정 → 커넥터 (또는 MCP)
**네이버 관련 항목이 있는지** 봐주세요.
- 있다 → 그 노트북에서 직접 대화할 때만 작동. Routine에는 연결 안 돼 있음.
- 없다 → 애초에 연결된 적이 없음.

### 5. 네이버 개발자센터
https://developers.naver.com → 내 애플리케이션
- 등록된 앱이 있는지, 있다면 **검색 API / 지역 검색**이 사용 설정돼 있는지
- 사용량 통계에 호출 기록이 있는지 ← **이게 제일 확실한 증거**

### 6. 네이버 검색광고 (키워드 검색량용)
https://searchad.naver.com → 도구 → API 사용 관리
- 라이선스가 발급돼 있는지 (키워드 월 검색량은 여기서만 정확히 나옵니다)

## 확인 결과에 따른 갈림길

| 4~6번 결과 | 해야 할 일 |
|---|---|
| 네이버 앱 등록이 **없다** | 개발자센터에서 앱 등록 → 지역 검색 API 사용 설정 → 커넥터/스크립트로 연결 |
| 앱은 있는데 **Routine에 연결 안 됨** | Routine을 다시 만들면서 커넥터 목록에 추가 |
| 연결돼 있는데 **호출 기록이 없다** | Routine이 꺼져 있어서 (현재 상태) — 켜면 해결 |

## 네이버 API를 붙이면 달라지는 것

| | 지금 (브라우저) | 네이버 API |
|---|---|---|
| 컴퓨터 켜져 있어야 함 | **예** | 아니오 |
| 네이버 도메인 차단 영향 | **받음** | 안 받음 |
| 주소·전화·영업시간 | 구글맵 대체 → 자주 누락 | 지역 검색으로 한 번에 |
| 주차 정보 | 9건 중 5건 누락 | 항목 자체가 없음 (API 미제공) |
| 키워드 검색량 | keywordsound.com 수동 | 검색광고 API로 정확히 |

**주차는 API로도 안 나옵니다.** 네이버 지역 검색 API 응답에 주차 항목이 없어요.
→ 주차만큼은 프롬프트에서 아예 빼거나 "방문 전 매장 문의" 고정으로 두는 게 맞습니다.
