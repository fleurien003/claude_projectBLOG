## ⚠️ 네이버 API HUB 이관 (2026-09-29 확인 — 여기 안 보고 또 틀리지 말 것)
네이버가 **Search API·Search Trend(검색어트렌드)·Shopping Insight(쇼핑인사이트)** 3개를 **개발자센터 → NAVER API HUB(NAVER Cloud Platform)** 로 이관 중. 공지: https://developers.naver.com/notice/article/32530

- 일정: 1단계 2026-06-25 API HUB 출시 · 2단계 **2026-07-31 개발자센터 신규 신청 차단(이미 지남)** · 3단계 2027-06-30 개발자센터 완전 종료(그 뒤엔 예전 키도 막힘)
- **지금(2026-09-29)은 이미 2단계를 지났기 때문에 검색어트렌드·쇼핑인사이트는 신규 신청 자체가 API HUB로만 가능하다.** 개발자센터 쪽으로 새로 뚫으려 하면 안 됨 — 이미 못 함.
- 예외: 검색 API 중 '쇼핑·책·전문자료' 검색은 이관 대상이 아니라 그냥 2026-07-31에 끝남(대체 없음).
- 바뀌는 것: 인증 체계(개발자센터 Client ID/Key → **API HUB 전용** Client ID/Key, 서로 다른 값), 계정(네이버 계정 → NCP 계정).

**엔드포인트·인증 (2026-09-29 직접 호출해서 확인 — 경로는 검증됨, 헤더 이름은 NCP API Gateway 공통 규칙이라 신뢰도는 높지만 실제 키로 최종 확인 전이라 100%는 아님):**
- 기본 주소: `https://naverapihub.apigw.ntruss.com` (구 `openapi.naver.com`으로 이 두 API 부르면 이제 안 됨)
- 검색어트렌드: `POST /search-trend/v1/search`
- 쇼핑인사이트(분야별 인기검색어): `POST /shopping/v1/category/keywords`
- 인증 헤더: `X-NCP-APIGW-API-KEY-ID`(Client ID) · `X-NCP-APIGW-API-KEY`(Client Secret) — **구 검색 API 헤더(`X-Naver-Client-Id`/`X-Naver-Client-Secret`)와 이름이 다르다. 섞어 쓰면 안 됨.**
- 필요한 키는 **NCP 콘솔에서 발급한 API HUB 전용 Client ID/Secret** — 지금 세션의 검색광고 키(`NAVER_AD_*`)와도, 옛 검색 API 키와도 전혀 다른 별개의 값이다. 이 키는 환경변수 `NCP_API_KEY_ID`·`NCP_API_KEY`로 이미 세션에 들어와 있다(2026-09-29 확인).

**2026-09-29 실제 키로 호출해서 검증한 결과 (중요 — 기대와 다름):**
- `POST /search-trend/v1/search` : ✅ 정상 동작 확인. `keywordGroups`에 넣은 키워드의 **날짜별 상대 검색 비율(0~100, 최댓값 100 기준)**을 돌려준다. 실측값(월 검색량)이 아니라 **트렌드 지수(상대값)** 다.
- `POST /shopping/v1/category/keywords` : `keyword` 파라미터가 **필수**다(빈 값·카테고리만 보내면 400 에러로 확인). 즉 **"이 분야에서 지금 뜨는 검색어가 뭐야?"를 물어보는 API가 아니라, 이미 아는 키워드들의 그 분야 안에서의 추이를 비교하는 API**다.
- **결론: 데이터랩 API(구버전이든 API HUB든)는 "분야별 인기검색어 TOP 500" 같은 순위 목록을 주지 않는다.** 그 TOP 500 화면은 `datalab.naver.com` 웹페이지 UI 전용 기능이고, 공식 API로는 원래 노출된 적이 없다(이관 전후 동일). 그래서 "이거 보면 주제 검색 안 해도 된다"는 기대는 **API로는 실현이 안 되고**, 은아님이 직접 그 웹페이지를 보고 캡처해주시는 방식만 가능하다.
- Search Trend API는 그래도 쓸모가 있다 — **후보 키워드가 이미 있을 때** 급등 판정을 검색광고 API 배수 계산보다 더 깔끔한 시계열로 보여줄 수 있음(도입 여부는 아직 결정 안 됨).

## 초안 쓰기 버튼 동작 (2026-09-22 수정)

상태를 `방문 완료`로 바꾸거나 "초안 쓰기"를 누를 때, **프롬프트가 없으면 먼저 프롬프트를 만들고
그 프롬프트로 초안을 씁니다.** 기본 정보만으로 바로 쓰지 않습니다.

- 확인창 버튼 문구 : ~~그대로 쓰기~~ → **`프롬프트 업데이트 후 쓰기`**
- 누르면 `writePromptNow()` 가 템플릿을 고르고 프롬프트를 쓴 뒤, 그 결과를 그대로 받아 초안을 씁니다.
- **프롬프트 만들기가 실패하거나 멈추면 초안도 쓰지 않습니다.** (규칙 없는 글이 나가는 걸 막음)

#### 어떻게 불리는가 — MCP 커넥터 (2026-09-23 확정)

**아티팩트는 `fetch()` 로 바깥을 못 부릅니다.** 2026-09-23에 화면에서 직접 확인했습니다 —
우리 중계 서버도, `api.github.com` 도 전부 `TypeError: Failed to fetch` 였습니다.
샌드박스가 외부 호출을 통째로 막습니다. **서버 문제가 아니었습니다.**

아티팩트가 바깥에 닿는 통로는 **뷰어의 claude.ai 커넥터 하나뿐**입니다.
그래서 중계 서버를 MCP 서버로 만들어 커스텀 커넥터로 등록했습니다.

```
커넥터 이름 : naver-blog-helper        ← 코드가 이 이름으로 찾는다. 바꾸면 안 됨
주소        : https://naver-blog-helper.onrender.com/mcp/<MCP_SECRET>/
도구        : keyword_volume · place_lookup · blog_read
```

- 프로토콜은 직접 짜지 않고 **FastMCP** 를 씁니다 (`stateless_http=True`, `json_response=True`).
- 도구는 기존 HTTP 라우트를 그대로 감싼 것이라 **어느 쪽으로 불러도 같은 답**이 나옵니다.
- 호출은 **뷰어 자격증명**으로 나가고 페이지 코드는 토큰을 보지 않습니다.
- 대시보드가 직접 부르므로 **Claude 토큰 0**. (제가 채팅에서 부르면 조회당 ~300토큰)

**실패는 코드별로 다르게 안내합니다.** 하나로 뭉뚱그리면 정작 화면을 살릴 행동이 안 보입니다.
`server_not_connected`(커넥터 추가) · `needs_reauth`(재연결) · `not_in_manifest`(허용 누르기) ·
`server_unavailable`(잠시 뒤 재시도, 1회만 자동) 등. `retryable` 표시된 것만 자동 재시도합니다.

> ⏳ **첫 조회가 느리거나 한 번 실패하는 건 정상입니다.** Render 무료 플랜이 15분 놀면 자고,
> 커넥터 연결 제한이 30초라 깨는 도중이면 실패합니다. **한 번 더 누르면** 됩니다.

#### 중계 서버 보호 (2026-09-23)

| 대상 | 방법 | 이유 |
|---|---|---|
| MCP | **경로 비밀값** `MCP_SECRET` → `/mcp/<값>/` 로만 열림 | 커스텀 커넥터의 고정 헤더 인증은 아직 베타라 화면에 없을 수 있음 |
| HTTP 라우트 | **IP 기준 시간당 120회** (`RATE_PER_HOUR`) | 토큰을 걸면 클로드 세션에서도 못 불러 작업이 막힘 |

`MCP_SECRET` 을 바꾸면 **커넥터 주소도 같이 고쳐야** 합니다. 안 고치면 404가 됩니다.
비밀값은 Render 환경변수로만 넣습니다. 코드에도 대화에도 남기지 않습니다.
