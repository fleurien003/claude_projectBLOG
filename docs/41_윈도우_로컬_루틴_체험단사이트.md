> 리뷰노트·레뷰·강남맛집 캠페인 정보를 클라우드에서 읽을 수 없다는 결론과, 그 대안.
> **2026-10-02 갱신**: 강남맛집은 렌더링 프록시(`https://r.jina.ai/<링크>`, `X-Return-Format: html`)로 로그인 없이 캠페인 본문(제공내역·키워드·방문 및 예약)이 읽혀 **클라우드 루틴이 직접 처리**합니다(`&guide=1` 페이지만 로그인 필요). 리뷰노트·레뷰는 비로그인에게 로그인 벽만 보여 프록시로도 불가 → 이 문서의 로컬 루틴 대상은 **리뷰노트·레뷰 두 곳**입니다.
> 은아님 윈도우(평일 낮 켜져 있음)의 Claude 앱 로컬 루틴으로 돌린다. 기존 할 일 "카톡 알림 루틴(월·목 14:15)"과 합친다.

## 1. 왜 클라우드로는 안 되나 (2026-10-01 실측)

| 사이트 | 확인한 것 | 결론 |
|---|---|---|
| 리뷰노트 | Next.js. 페이지는 열리지만 본문은 `GET /api/campaign?id=<번호>` 로 받아오고, 이 API가 **401(로그인 필요)** | 로그인 세션 필요 |
| 레뷰 | AngularJS. API 호스트 `api.weble.net`, `GET /campaigns/<번호>` 가 **401 "Full authentication is required"**. 토큰은 accounts.revu.net 로그인(Bearer) | 로그인 세션 필요 |
| 강남맛집 (xn--939au0g4vj8sq.net) | 클라우드에서는 **연결 리셋**, Render(미국)에서는 **연결 시간 초과**. 둘 다 해외 IP | 한국 IP에서만 열리는 것으로 보임 ⚠️미확인 (은아님 PC에서 `curl -I https://xn--939au0g4vj8sq.net/cp/?id=2301583` 한 번 돌려보면 확정) |

| 미스터블로그 | 로그인 페이지로 리다이렉트 | 로그인 세션 필요 |

쿠키·토큰을 중계 서버에 저장하는 방법은 쓰지 않는다. 만료되면 매번 다시 넣어야 하고, 유출되면 계정 전체가 열린다.

## 2. 로컬 루틴이 할 일 (월~목 14:15, 윈도우 Claude 앱, 브라우저는 로그인된 상태)

1. **선정 목록 확인** (`docs/03` 3번 주소)
   - 리뷰노트 마이페이지 → 나의 캠페인 → 진행중
   - 강남맛집 마이페이지 → 선정
   - 레뷰 `https://www.revu.net/mypage/campaigns?status=accepted`
   - 로그인이 풀린 사이트는 조용히 건너뛰지 말고 보고 맨 위에 "OO 로그인 풀림"이라고 적는다. 로그인 시도는 하지 않는다.
2. **대시보드와 대조** — `campaigns` 에 같은 업체(지역 수식어·공백 무시)가 있는지. 없으면 새로 등록(`name`, `platform`, `link`, `created` 오늘, `status:'시작 전'`, `auto_status:'pending'`, note `🤖 (날짜) <플랫폼> 마이페이지에서 등록`). 있으면 `link`·`platform` 이 비어 있을 때만 채운다.
3. **캠페인 상세 읽기** — 선정된 건의 캠페인 페이지를 브라우저로 열어 `offer`(제공 내역·체험 가능 요일/시간·예약 주의), `due`(리뷰 마감), `amount`, `reserve_phone`(담당자 번호, 본문 노출 금지), 업체 요청 키워드(있으면 `offer` 끝에 `요청 키워드: …`)를 채운다. 이미 값이 있는 칸은 덮어쓰지 않는다. 채웠으면 `auto_status:'pending'` 그대로 두고 note `📄 (날짜) 캠페인 상세 반영` — 그러면 클라우드 루틴 4)가 다음 날 10시에 프롬프트를 쓴다.
4. **카톡 알림** (원래 계획) — 선정 알림 카톡이 와 있으면 1~3을 그 업체에 우선 적용.
5. 보고: 새로 등록 N건(업체·플랫폼), 상세 반영 N건, 로그인 풀림 사이트.

## 리뷰노트 쿠키 방식 (2026-10-02, 완전 자동화 선택지)
윈도우 로컬 루틴 대신, 중계 서버(Render)가 르나의 로그인 쿠키로 리뷰노트 API(`/api/campaign?id=`)를 읽는 방식. 코드 초안은 `docs/patches/naver-blog-helper_reviewnote-cookie.patch`.

1. **쿠키 복사** (리뷰노트에 로그인된 윈도우 크롬): 캠페인 페이지 → F12 → Network → 새로고침 → `campaign?id=…` 요청 클릭 → Headers → Request Headers → `Cookie:` 값 전체 복사. (Application 탭 → Cookies 에서 하나씩 모아도 됨. 형식은 `이름=값; 이름=값; …`)
2. **Render에 저장**: dashboard.render.com → naver-blog-helper → Environment → Add Environment Variable → Key `REVIEWNOTE_COOKIE`, Value에 붙이기 → Save Changes (자동 재배포 2~3분).
3. **코드 반영**: 완료(2026-10-02, naver-blog-helper 커밋 2cf0412, Render 자동 배포). 더미 쿠키로 401 → "쿠키가 만료됐습니다" 경로까지 확인. 성공 경로(응답 필드)는 실제 쿠키가 들어간 뒤 4단계에서 확인. 루틴 v3.6은 리뷰노트를 `/page`로 먼저 읽고 만료면 `raw`로 돌아간다.
4. **확인**: `curl -sS -G https://naver-blog-helper.onrender.com/page --data-urlencode "url=https://www.reviewnote.co.kr/campaigns/1450354"` → `{title, text}`가 오면 성공. 이후 루틴 4)가 리뷰노트 링크도 `/page`로 읽는다.
5. **만료**: 쿠키가 죽으면 `/page`가 "리뷰노트 쿠키가 만료됐습니다"를 돌려주고 루틴이 보고에 적는다 → 1·2 반복. 수명은 ⚠️미확인(첫 만료 때 기록). 브라우저에서 **로그아웃하면 즉시 무효**가 되니 로그아웃하지 않는다.
6. **보안**: 쿠키 = 계정 열쇠. 채팅·git·대시보드 note에 절대 쓰지 않고 Render 환경변수에만 둔다. 패치의 응답 필드 이름은 ⚠️미검증이라 첫 성공 응답을 보고 한 번 다듬는다.
