# 홈피드 규칙

> 홈피드 카드·초안·루틴을 다루기 **전에 반드시 이 문서를 읽는다.** (2026-09-24 CLAUDE.md 에서 옮겨옴)
> 근거 자료는 docs/05·06·07.


## 홈피드 규칙 (맥북 세션 확정, 2026-09-22 반영)

- **시의성이 가장 중요.** 돌발형은 최근 3일(연예는 이틀), 계절형은 검색이 붙기 시작할 때.
- 안 본 것도 본 것처럼 1인칭 경험으로 쓴다. **숫자는 카드(출처)에 있는 것만.**
- 1,300~1,700자, 소주제 3~5개, 해시태그 30개(카드의 `hashtags`), `main_keyword` 5회 이상.
- 제휴 링크 최대 3회. **링크만 있는 소주제 금지.** 마무리는 내용에 맞게 자연스럽게.
  수수료 안내 문구는 쓰지 않는다 (르나 전용 스티커가 따로 있음).
- **"협찬" 단어는 홈피드에서만 허용** (남의 협찬 이야기를 할 수 있음).
- 사진 기사(`[HD포토]` 등)는 제외.

### 키워드 검색량 조회 (2026-09-23 신설)

대시보드 **홈/홈피드/체험단 버튼 바로 밑 검색창**에 키워드를 넣으면 나옵니다.

- 총 검색량 · PC/모바일 건수와 비율 · 경쟁 정도 · 통계 기간
- 연관 키워드 5개 (검색량 많은 순, 눌러서 바로 재조회)
- **급등 판정** (아래)

브라우저가 중계 서버 `GET /keyword?q=` 를 직접 부릅니다. **Claude 토큰은 안 듭니다.**

> ⏳ **"중계 서버에 연결하지 못했어요"가 뜰 때** — Render 무료 플랜은 15분쯤 놀면 잠들고,
> 배포 직후에는 재시작 중이라 연결이 거부됩니다. 그래서 **즉시 → 3초 뒤 → 8초 뒤 세 번 부르고**
> 한 번에 90초까지 기다립니다. 그래도 안 되면 **[다시 시도]** 버튼이 뜹니다.
> 배포 직후라면 1~2분 뒤에 됩니다. 매번 기다리는 게 싫으면 Render 유료 플랜($7/월)은 잠들지 않습니다.

#### 급등 판정 — Iglewicz & Hoaglin 수정 Z-점수

> ⚠️ **데이터 소스가 둘로 나뉩니다 (2026-09-29부터).** 위 "키워드 검색량 조회" 수동 위젯(대시보드 검색창)은 그대로 중계 서버 `/keyword`가 계산해서 줍니다. 반면 **자동 루틴(홈피드 ①②)은 이제 검색어트렌드 API(NAVER API HUB)를 직접 불러서 같은 공식으로 루틴 세션 안에서 자체 계산**합니다(근거: `docs/30_대시보드_중계서버.md`). 공식은 동일하지만 원본 데이터가 다르므로(중계 서버는 검색광고 API 기반, 루틴은 검색어트렌드 API 기반) 같은 키워드라도 점수가 살짝 다를 수 있습니다 — 둘 다 유효하되 출처가 다르다는 점만 기억하면 됩니다. 자동 카드의 `trend_note`엔 "score=" 표기, 수동 위젯은 기존 "배수" 표기를 씁니다.

| 점수 | 표시 | 근거 |
|---|---|---|
| 베이스라인 0 → 현재 발생 | 🚀 신규 급등 | Google Trends `Breakout`(+5000%)과 같은 개념 |
| **3.5 이상** | 🔥 급등 | **Iglewicz–Hoaglin 권고 임계값** |
| 2.0 ~ 3.5 | 📈 상승 | 경험규칙 2σ ≈ 상위 5% |
| −2.0 ~ 2.0 | ➖ 평탄 | 정상 범위 |
| −2.0 이하 | 📉 하락 | 하위 5% |

**왜 "몇 배 올랐나"로 안 재는가** — 직전 구간이 0이면 배수를 낼 수 없습니다.
배수로 재면 **새로 뜬 키워드가 0으로 계산돼 "하락"으로 찍힙니다.** 제일 중요한 경우를
정반대로 판정하는 거예요. Google Trends가 +5000%를 `Breakout` 이라는 별도 라벨로
빼둔 것도 같은 이유입니다.

**왜 평균·표준편차가 아닌가** — 스파이크가 평균을 끌어올려 자기 자신을 가립니다(masking).
중앙값과 MAD는 붕괴점이 50%라 데이터 절반이 튀어도 기준선이 안 흔들립니다.

**창** : 60일 (베이스라인 53일 + 최근 7일).
최근 7일을 **각각** 점수 내고 그 **중앙값**을 씁니다 — 하루만 튄 값에 안 속습니다.
7일로 묶는 건 **요일 주기가 7일**이라서예요. 3일로 보면 주말에 검색이 몰리는
맛집·여행 키워드가 매주 급등으로 뜹니다.

**데이터 출처가 둘로 나뉘는 이유** — 데이터랩은 절대 검색량을 주지 않습니다
(구간 최댓값 100 기준 상대 비율만. 절대값은 NCP 데이터박스 유료 구독).
그래서 **총 검색량은 검색광고 API, 추이는 데이터랩**입니다.

#### 검색량이 적으면 판정하지 않습니다 (2026-09-23 르나 승인)

하루 n건이 검색되는 키워드의 **순수 잡음은 포아송 √n**, 즉 상대 오차가 `1/√n` 입니다.
데이터랩 ratio 는 여기에 정수 양자화까지 해서, 저볼륨은 하루 3~4건 차이로 배수가 몇 배씩 튑니다.

| 월 검색량 | 하루 | 잡음 | 처리 |
|---|---|---|---|
| **3,000회 이상** | 100건 | ±10% | ✅ 신뢰 |
| 1,000 ~ 3,000회 | 33~100건 | ±17% | ⚠️ 참고 — **2배 이상 급등이면 유효** |
| **1,000회 미만** | 33건 미만 | ±26% 이상 | ⚪ **판정 보류** |

> 하드컷 3,000회로 하면 **장원영가방(월 1,060회 · 4.97배)** 같은 진짜 신호가 같이 죽습니다.
> 그래서 두 칸으로 나눴습니다. **벚꽃명소(월 460회)가 9월에 21배 급등으로 찍혔던 건** 걸러집니다.

#### 📉 피크 지남 (2026-09-23 신설)

점수는 **중앙값(평상시) 기준**이라, 큰 스파이크가 지나가고 평상시로 돌아오면 "평탄"으로 읽습니다.
그래서 **최고점이 최근 7일 밖 + 평균 0.7배 미만**이면 `📉 피크 지남`으로 바꿉니다.

> 실제로 `들쥐`가 **배수 0.41인데 점수 0.42(평탄)** 으로 나왔습니다. 이제 📉로 잡힙니다.

> 🔬 **2026-09-23 교훈 — 만들기 전에 공신력 있는 자료로 리서치부터 한다.**
> 처음에 "최근 7일 평균 ÷ 직전 21일 평균, 2배 이상이면 급등"을 표로 내놨는데
> 전부 감으로 정한 숫자였습니다. 르나가 근거를 물어 리서치하고 나서야
> 계산식 자체의 결함까지 드러났습니다. **기준을 표로 제시할 때는 출처를 함께 답니다.**

### 키워드 검색 규칙 (2026-09-23 르나 확정)

#### 원칙 0 — 기자의 말이 아니라 검색창의 말

뉴스 제목 단어를 그대로 치지 않습니다. `○○대책` `○○방안` `○○규제` `○○논란` 은 **기사 용어**입니다.

```
부동산대책   10회 미만   연관 키워드 0개    ← 기자의 말
부동산규제   10회 미만   연관 키워드 0개
디딤돌대출   70,800회                      ← 사람의 말
보금자리론   74,500회
```

#### 신호 읽는 법

| 결과 | 뜻 | 할 일 |
|---|---|---|
| **10회 미만 + 연관 0개** | 죽은 키워드. 광고 DB에도 없음 | ❗ **버리지 말고 표현을 바꿔 다시 찾는다** |
| 10회 미만 + 연관 있음 | 표기만 틀림 | 연관 키워드 중에서 고른다 |
| 검색량 있음 + ➖ 평탄 | 항시 키워드 | 해시태그로만 |
| **3,000회+ 🔥 급등** | 🎯 | **채택** |

> **연관 키워드 0개가 제일 확실한 사망 신호입니다.**

#### 사다리 — 위에서 아래로 내려가며 친다

| 단계 | 형태 | 예 |
|---|---|---|
| 1 | **고유명** (제도·작품·인물·브랜드) | `양도소득세` `디딤돌대출` `스캔들` `장원영` |
| 2 | **고유명 + 행동** | `디딤돌대출조건` `양도소득세계산` |
| 3 | **고유명 + 궁금증** | `스캔들출연진` `스캔들결말` `○○몇부작` |
| 4 | **상위 일반어** | `부동산` `대출` `넷플릭스` — 항시 확인용, **노리지 않음** |

**지름길** — 조회하면 연관 키워드 5개가 같이 옵니다. 그중 급등한 걸 다시 치면 사다리를 자동으로 탑니다.

#### 멈추는 조건

- 1~3단계에서 **월 3,000회 이상 + 🔥 급등**이 하나라도 나오면 **멈춘다.**
- **5회 쳐서 전부 10회 미만이면 그 소재는 검색 수요가 없다.** 카드를 버린다.
- 한 소재당 조회 상한 **7회** (⚠️ 이 숫자는 근거 없는 판단값)

### 글 안 키워드 배치 (2026-09-23)

| 자리 | 넣는 것 | 노리나 |
|---|---|---|
| **제목 + `main_keyword`** | **가장 큰 급등 키워드 하나** | ✅ 승부처 |
| **소주제 제목 1~5** | **급등 롱테일** (`출연진` `결말` `줄거리` `몇부작`) | ✅ **실제로 먹는 자리** |
| 본문 | 위 키워드들 자연스럽게 | — |
| **해시태그 30개** | 항시 대형 + 롱테일 섞어 | ❌ 노출 보조용, 순위 목적 아님 |

**근거 — Ahrefs 300만 쿼리 연구**
- 1위 페이지는 평균 1,000개(중앙값 400개) 키워드로 top10에 같이 든다 → **키워드를 더 넣어도 분산되지 않는다**
- 월 1,000회 이상 **2~3개 동시 상위는 흔하다**
- 월 **1만 이상을 한 글로 두 개 먹는 건 매우 드물다** → **초대형은 하나만 노린다**
- 카니발라이제이션은 **"여러 글이 같은 키워드를 노릴 때"** 생긴다. 한 글 안에서는 해당 없음

그래서 **항시 초대형(넷플릭스 164만·넷플릭스추천 11.7만)은 못 먹습니다.** 해시태그로만 씁니다.
대신 **급등 키워드의 롱테일 변형**이 진짜 판입니다 — 스캔들 카드 실측에서 `출연진` 59,600(🔥57.6배)
`결말` 28,500 `줄거리` 22,030 `몇부작` 7,750 전부 급등이었습니다.

> ⚠️ 검색광고 API의 **경쟁 정도(`compIdx`)는 광고 경쟁**입니다. 블로그 상위노출 난이도가 아닙니다.

### 띄어쓰기 — 둘 다 넣습니다 (2026-09-23 르나 확정)

| 형태 | 자리 | 횟수 |
|---|---|---|
| **붙인 형태** `장원영가방` | 본문 | **3회 이상** |
| **띄운 형태** `장원영 가방` | **제목** + 본문 | 합쳐서 5회 이상 |

- 네이버는 **형태소 단위**로 분석하고, 띄어쓰기에 따라 노출이 달라진 사례가 보고됩니다.
  어느 쪽이 맞는지 단정할 공식 자료는 **못 찾았습니다.**
- 한 글에 여러 표기를 넣어도 분산되지 않으므로(위 Ahrefs) **둘 다 겁니다.**
- **제목은 띄운 형태** — 사람이 먼저 읽고, 홈피드는 **CTR·체류시간**으로 돌아갑니다. (르나 지정)
- 검색광고 API는 공백을 지우고 조회하므로 **어느 형태를 더 많이 치는지는 알 수 없습니다.**

`tools/feedcheck.py` 가 `메인 키워드(붙여서)` / `메인 키워드(합계)` / `제목 띄어쓰기` 세 줄로 따로 셉니다.

### 발행 전 검사 (2026-09-23 신설)

```
python3 tools/feedcheck.py <초안.txt> --keyword 장원영가방
python3 tools/feedcheck.py <카드.json>      # items 문서면 카드에서 키워드를 읽는다
```

❌ 는 고쳐야 하는 것, ⚠️ 는 눈으로 확인할 것입니다.
검사 항목 : 본문 1,300~1,700자 · 소주제 3~5개 · 해시태그 정확히 30개(중복 0) ·
메인 키워드 5회 이상 + 제목에 1회 · `~`와 `!` 합쳐 4개 이하 · 한 문단 2문장 이하 ·
마크다운 기호 없음 · 소주제 번호 `1. 2. 3.` · 날짜 표현(⚠️)

> **만든 계기 — 9/21 장원영 카드.** 카드의 `main_keyword`는 `장원영가방`인데
> 초안은 **"장원영 가방"(띄어쓰기)** 으로 써서 메인 키워드가 본문에 **0회** 들어갔습니다.
> 상위노출이 목적인 글에서 이게 제일 치명적인데 아무도 못 잡고 있었습니다.
> **키워드는 띄어쓰기까지 글자 그대로 씁니다.**

### 홈피드형 템플릿 (h_*) 은 소주제 뼈대만 씁니다 (2026-09-23)

`buildFeedPrompt` 는 카드 분류에 맞는 `h_*` 템플릿에서 **`5️⃣ 본문 구성` 부분만** 뽑아 씁니다.
템플릿 본문을 통째로 붙이지 않습니다 — `h_*` 안에 **협찬 표기·내 경험 우선·재료 반영처럼
체험단 전용 규칙이 섞여 있어서** 홈피드 글에 붙이면 지시가 서로 어긋납니다.

| 카드 분류 | 템플릿 |
|---|---|
| `celeb_fashion` `celeb_issue` | `h_celeb` |
| `finance` | `h_finance` |
| `ott` | `h_ott` |
| `travel_issue` `travel_spot` | `h_travel` |
| `kurly_pick` | **`h_kurly` — 아직 없음** (없으면 뼈대 없이 나감) |

## 🔜 다음 대화에서 바로 시작 — 홈피드 카테고리별 기준 (2026-09-23 이어서)

**2026-09-23 대화가 길어져 여기서 끊고 새 대화로 넘깁니다. 이것만 정하면 홈피드 고도화가 끝납니다.**

### 이미 확정된 재료 (위 "홈피드 규칙" 참고)
급등 판정 · 저볼륨 가드 · 키워드 검색 규칙(원칙 0 + 사다리) · 띄어쓰기 · 글 안 배치.

### 카테고리별로 정할 것은 딱 두 가지
1. **이벤트 키워드를 어디서 찾나** (제도 고유명 / 작품 제목 / 인물+아이템 …)
2. **리드타임** (며칠 전에 써야 하나)

### 이 대화에서 도달한 안 — 카테고리가 아니라 **키워드 유형**으로 나눈다

모든 카테고리에 **항시형(head)** 과 **이벤트형(급등)** 이 공존합니다.
`넷플릭스`(164만, 평탄) 옆에 `스캔들`(88만, 🔥30.8배)이 있고,
`상속세`(2.8만, 평탄) 옆에 정책 고유명이 있습니다. **판정 대상을 이벤트 키워드로 잡아야 합니다.**

근거는 **QDF(Query Deserves Freshness)** — 검색량이 급등한 쿼리에만 최신 문서를 우대합니다.
급등 없는 항시 키워드에 새 글을 쓰면 최신성 가산이 없고, C-Rank 축적 블로그와 정면승부가 됩니다.
**급등 키워드가 르나가 이길 수 있는 유일한 자리입니다.**
